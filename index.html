Problem Solving for Programming

Module Core Purpose

This module does not teach a specific programming language. Instead, it teaches the foundational problem-solving and algorithmic logic skills needed to learn and program in any programming language.

Time Allocation

Most of a software developer's time is spent solving problems rather than typing code:

Key Principles

  • Programming Defined: Writing detailed instructions for a computer to carry out specific tasks.
  • Core Competencies: Logical reasoning, attention to detail, and mathematical reasoning.
  • Progression Path: Commitment, daily practice, repetition, curiosity, and research.

Software Development Life Cycle (SDLC)

Software development follows a cyclical sequence of six key stages:

  1. Planning: Plan the overall project scope.
  2. Analysis: Define requirements and specifications.
  3. Design: Design the system architecture.
  4. Implementation: Code and build software modules.
  5. Testing & Integration: Evaluate and merge code.
  6. Maintain: Fix bugs and implement updates.

Categories of Software

  • Systems Software: Drives hardware (e.g., Windows, macOS, Linux).
  • Application Software: Performs user tasks (e.g., Office, Minecraft, Email).
  • Software Tools: Languages to build software (e.g., Python, C++, Java).

Problem-Solving Techniques

  • Visual Representation: Diagrams, tables, and charts.
  • Simpler Analogous Problems: Solve smaller versions first.
  • Finding Patterns: Leverage structural logic.
  • Intelligent Guessing: Systematic elimination.

Mindset & Detail Orientation

  • Mathematical Reasoning: Essential logical base for programmers.
  • Analytical Deconstruction: Check for all failure points.
  • Continuous Refactoring: Never assume code is optimal because it runs.

Solution to Program Pipeline

Express natural language solutions as algorithms before writing code:

  • Algorithm: A finite, structured set of step-by-step instructions.
  • Computer Models: Simplified representations to simulate systems safely.
  • Generalisability: Algorithms solve all variations of a given problem.

Abstraction & Optimisation

  • Abstraction: Removing unnecessary lower-level detail. Uses Hierarchical Task Analysis (HTA) or Top-Down Refinement.
  • Optimal Algorithm:
    1. Uses minimum execution steps.
    2. Avoids errors under unforeseen conditions.
    3. Features modular components designed for reusability.

3 Basic Constructs

Any computational problem can be solved using these three constructs:

1Sequence
The precise logical order in which steps are executed.
2Selection
Branching execution paths based on logical conditions (IF/ELSE).
3Iteration
Repeating steps until a condition is met (FOR/WHILE loops).

Flowchart Standard Symbols

Flowcharts visually show logical constructs vertically in columnar order.

Shape Name Purpose
Oval Start / End entry or termination.
Arrow Direction of control flow.
Parallelogram Input / Output operations.
Rectangle Internal process / calculations.
Diamond Conditional Decision point.

Pseudocode Standards (Gaddis Style)

  • Each statement is numbered on its own line ending with `;`.
  • Begins with PROGRAM <Title> and ends with END.
  • Keywords are written in UPPERCASE.
PROGRAM <SnackVending>
1. Process payment;
2. Make selection;
3. Dispense snack;
4. Return change;
END

Pros & Cons of Pseudocode

Advantages
  • Language independent; easy to read.
  • Focuses strictly on logic.
Disadvantages
  • Time-consuming to update manually.
  • Cannot be directly executed on a computer.

  4. 4. Acceptance Testing: User satisfaction check.
